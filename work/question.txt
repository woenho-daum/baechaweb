현재 Python으로 개발 중인 배차 관련 웹시스템을 전면 재개발 하고 싶다
「설문 관리 기능」도 추가하고 싶다.

단순히 SQL INSERT 문으로 설문을 등록하는 방식이 아니라,
관리자가 웹 화면에서 설문을 생성하고 수정/조회/삭제할 수 있도록
표준적인 설문 관리 화면을 만들고 싶습니다.

## 1. 현재 시스템 환경

아래에 현재 프로젝트의 정보를 제공합니다.

* 개발 언어: Python
* 웹 프레임워크: [Flask / FastAPI / jwt / 기타]
* DB: SQLite

* 현재 프로젝트 파일 구조:

baechaweb\sqlite -> 데이터베이스 및 관련 파일들 저장소
	\sqlite\survey.db
baechaweb\templates -> html  템플릿 보관소
	\templates\baecha_intro.html
	\templates\baechaweb.html
baechaweb\baechaweb.py	->라우팅된 왭서비스를 실제처리하는 앱 중 하나로 설문지 하나다 하나씩 만들 예정임
baechaweb\main.py	-> Flask 메인 앱으로 웹페이지 라우팅만 수행

* 현재 웹 프로그램의 메인 실행 파일:
	---- main.py 의 내용----
from flask import Flask, make_response, render_template  # type: ignore

from baechaweb import auth, entry, survey

app = Flask(__name__)

@app.route("/")
def intro():
    response = make_response(
        render_template("baecha_intro.html")
    )

    # 기존 JWT 삭제
    response.delete_cookie("access_token")

    return response

@app.route("/baechaweb", methods=["GET"])
def baechaweb():
    response = make_response(entry())
    # 기존 JWT 삭제 
    response.delete_cookie("access_token")
    
    return response

@app.route("/baechaweb/auth", methods=["POST"])
def baechaweb_auth():
    return auth()

@app.route("/baechaweb/survey", methods=["GET","POST"])
def baechaweb_survey():
    return survey()


if __name__ == "__main__":
    app.run(debug=True)
	

설문과 관련된 현재 Python 파일
--- 현재 baechaweb.py 내용----
import datetime
import sqlite3

import jwt  # type: ignore # 추가 필요: pip install PyJWT
from flask import jsonify, make_response, render_template, request  # type: ignore

DB_PATH = "./sqlite/survey.db"
SECRET_KEY = "your-very-secret-key-change-this"  # 안전한 비밀키로 변경하세요


def get_db():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    return conn


def entry():
    conn = get_db()
    try:
        survey = conn.execute("""
            SELECT 
                survey_id, 
                survey_title, 
                description, 
                is_active 
            FROM survey_master 
            WHERE survey_id = 1
        """).fetchone()
    finally:
        conn.close()

    if survey is None:
        return "설문 정보를 찾을 수 없습니다.", 404

    return render_template("baechaweb.html", survey=survey)


def auth():
    data = request.get_json(silent=True) or {}
    phone = data.get("phone", "").strip()
    phone = "".join(ch for ch in phone if ch.isdigit())

    if not phone:
        return jsonify({"success": False, "message": "전화번호를 입력해 주세요."}), 400

    conn = get_db()
    try:
        driver = conn.execute(
            """
            SELECT 
                name, 
                phone, 
                dsl.completed, 
                dsl.answer_date 
            FROM drivers  
            inner JOIN drivers_survey_link dsl 
            ON name = dsl.driver_name 
            WHERE phone = ?
            """,
            (phone,),
        ).fetchone()
    finally:
        conn.close()

    if driver is None:
        return jsonify(
            {"success": False, "message": "등록된 전화번호를 찾을 수 없습니다."}
        ), 404

    # 1. 인증 성공 시 JWT 토큰 생성 (유효기간: 2시간)
    payload = {
        "phone": driver["phone"],
        "name": driver["name"],
        "exp": datetime.datetime.utcnow() + datetime.timedelta(hours=2),  # noqa: DTZ003
    }
    token = jwt.encode(payload, SECRET_KEY, algorithm="HS256")

    # 2. JSON 응답 생성
    response_data = {
        "success": True,
        "name": driver["name"],
        "phone": driver["phone"],
        "completed": driver["completed"],
        "answer_date": driver["answer_date"],
    }

    resp = make_response(jsonify(response_data))

    # 3. 브라우저 쿠키에 JWT 토큰 설정 (HttpOnly로 보안 강화)
    resp.set_cookie(
        "access_token", token, httponly=True, secure=False
    )  # HTTPS 환경인 경우 secure=True로 설정

    return resp


def survey():
    """/baechaweb/survey

    세션/쿠키에 담긴 JWT 토큰을 검증하여 인증된 사용자만 접근 허용
    """
    # 쿠키에서 JWT 토큰 가져오기
    token = request.cookies.get("access_token")

    if not token:
        return jsonify(
            {
                "success": False,
                "message": "인증 정보가 없습니다. 다시 로그인해 주세요.",
            }
        ), 401

    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
        phone = payload["phone"]
    except (jwt.ExpiredSignatureError, jwt.InvalidTokenError):
        return "유효하지 않거나 만료된 인증 정보입니다. 다시 로그인해 주세요.", 401

    # 필요하다면 DB에서 설문 데이터 조회
    conn = get_db()
    try:
        driver = conn.execute(
            """
            SELECT 
                name, 
                phone, 
                dsl.completed, 
                dsl.answer_date 
            FROM drivers  
            inner JOIN drivers_survey_link dsl 
            ON name = dsl.driver_name 
            WHERE phone = ?
            """,
            (phone,),
        ).fetchone()
    finally:
        conn.close()

    if driver is None:
        return "사용자 정보를 찾을 수 없습니다.", 404

    if driver["completed"] == "1":
        return "이미 설문을 완료하였습니다.", 405
    
    # JSON 대신 실제 설문조사 HTML 페이지를 렌더링하여 반환
    # return render_template("survey_form.html", driver=driver)

    # 검증된 전화번호를 바탕으로 DB 조회 수행
    conn = get_db()
    try:
        driver = conn.execute(
            """
            SELECT 
                name, 
                phone, 
                shift_day, 
                off_day, 
                childcare_day 
            FROM drivers 
            WHERE phone = ?
        """,
            (phone,),
        ).fetchone()
    finally:
        conn.close()

    if driver is None:
        return jsonify(
            {"success": False, "message": "등록된 전화번호를 찾을 수 없습니다."}
        ), 404

    return jsonify({"success": True, "name": driver["name"], "phone": driver["phone"]})


# 2. 현재 DB 구조

현재 설문 관련 DB 테이블은 다음과 같습니다.

CREATE TABLE IF NOT EXISTS drivers (
	name            TEXT PRIMARY KEY,
	phone           TEXT NOT NULL UNIQUE,
	shift_day       TEXT NOT NULL CHECK (shift_day IN ('월','화','수','목','금','토','일')),
	off_day         TEXT NOT NULL CHECK (off_day IN ('월','화','수','목','금','토','일')),
	childcare_day   TEXT CHECK (
			childcare_day IS NULL OR childcare_day IN ('월','화','수','목','금','토','일')
	),
	childcare_start TEXT NULL CHECK (
			childcare_start IS NULL OR (
				length(childcare_start) = 10 AND 
				strftime('%Y-%m-%d', childcare_start) = childcare_start
			)
	),
	childcare_end   TEXT NULL CHECK (
			childcare_end IS NULL OR (
				length(childcare_end) = 10 AND 
				strftime('%Y-%m-%d', childcare_end) = childcare_end
			)
	),
	CHECK (shift_day <> off_day)
);

CREATE INDEX IF NOT EXISTS idx_drivers_off_day ON drivers(off_day);
CREATE INDEX IF NOT EXISTS idx_drivers_shift_day ON drivers(shift_day);
CREATE INDEX IF NOT EXISTS idx_drivers_childcare_day ON drivers(childcare_day);
	 
CREATE TABLE survey_master (
    survey_id       INTEGER PRIMARY KEY AUTOINCREMENT,
    survey_title    TEXT NOT NULL,
    description     TEXT,
    is_active       INTEGER NOT NULL DEFAULT 0 CHECK (is_active IN (0,1,2,3)) --현재 개발중인지, 설문중인지, 관리중인지, 종료된 것인지...
);

CREATE UNIQUE INDEX ux_survey_master_active
ON survey_master(is_active)
WHERE is_active = 1;

CREATE TABLE drivers_survey_link (
    driver_name    TEXT NOT NULL,
    survey_id      INTEGER NOT NULL,
    completed      INTEGER NOT NULL DEFAULT 0 CHECK (completed IN (0,1)),
    answer_date    DATETIME NULL,
    created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    PRIMARY KEY (driver_name, survey_id),

    FOREIGN KEY (driver_name)
        REFERENCES drivers (name)
        ON DELETE CASCADE
        ON UPDATE CASCADE,

    FOREIGN KEY (survey_id)
        REFERENCES survey_master (survey_id)
        ON DELETE CASCADE
);

CREATE INDEX idx_sdl_survey_id
ON drivers_survey_link (survey_id);

CREATE TABLE survey_questions (
    survey_id       INTEGER NOT NULL,
    question_no     INTEGER NOT NULL,
    question_text   TEXT NOT NULL,
    question_type   TEXT NOT NULL CHECK (
        question_type IN ('single','multi','text')
    ),
    is_required     INTEGER NOT NULL DEFAULT 1 CHECK (is_required IN (0,1)),

    PRIMARY KEY (survey_id, question_no),

    FOREIGN KEY (survey_id)
        REFERENCES survey_master (survey_id)
        ON DELETE CASCADE
);

CREATE INDEX idx_questions_survey
ON survey_questions(survey_id, question_no);

CREATE TABLE survey_options (
    survey_id       INTEGER NOT NULL,
    question_no     INTEGER NOT NULL,
    option_no       INTEGER NOT NULL,
    option_text     TEXT NOT NULL,

    PRIMARY KEY (survey_id, question_no, option_no),

    FOREIGN KEY (survey_id, question_no)
        REFERENCES survey_questions(survey_id, question_no)
        ON DELETE CASCADE
);

CREATE TABLE survey_answers (
    driver_name     TEXT NOT NULL,
    survey_id       INTEGER NOT NULL,
    question_no     INTEGER NOT NULL,
    option_no       INTEGER,
    answer_text     TEXT,

    PRIMARY KEY (
        driver_name,
        survey_id,
        question_no,
        option_no
    ),

    FOREIGN KEY (driver_name)
        REFERENCES drivers(name)
        ON DELETE CASCADE,

    FOREIGN KEY (survey_id, question_no)
        REFERENCES survey_questions(survey_id, question_no)
        ON DELETE CASCADE,

    FOREIGN KEY (
        survey_id,
        question_no,
        option_no
    )
        REFERENCES survey_options(
            survey_id,
            question_no,
            option_no
        )
        ON DELETE CASCADE
);

기사 기본정보 테이블인 `drivers`는 다른 곳에서 생성하고 데이타도 일괄 입력합니다
기사 이름은 중복되지 않는다는 전제입니다.

# 4. 새로 만들고 싶은 기능

## A. 설문 목록 화면

관리자가 들어가면 등록된 설문을 목록으로 볼 수 있어야 합니다.


# 5. 설문 기본정보 입력/수정 화면

새 설문을 만들 때 먼저 기본정보를 입력합니다.

특히 현재의 설문 제목은 다음과 같이 변경할 예정입니다.

「배차근무표 생성을 위한 의견청취」

기본정보에는 최소한 다음 항목이 필요합니다.


기본정보에 대해서도

* 등록
* 조회
* 수정
* 삭제

모두 가능해야 합니다.

# 6. 실제 설문 문항 관리

기본정보를 저장한 후 해당 설문의 문항을 관리합니다.

질문과 선택지 모두

* 등록
* 조회
* 수정
* 삭제

가능해야 합니다.

가능하다면 질문 순서를 변경할 수 있도록 표 형태로 질분및 답변 번호를 지정할 수 있어야 합니다.

# 7. 선택지 관리

single 또는 multi 질문인 경우 선택지를 입력할 수 있어야 합니다.

예:


[+ 선택지 추가]

선택지 순서 변경도 가능하면 좋습니다.

# 8. 설문 대상자 관리

현재 `drivers_survey_link`를 사용하고 있습니다.

설문 마스터가 입력되면 일괄 등록될 필요 있음

# 9. 설문 미리보기

관리자가 실제 기사에게 보이는 설문 화면을
미리 확인할 수 있는 화면 필요


# 10. 응답 데이터는 기존 구조를 최대한 유지

현재 `survey_answers` 구조는 그대로 활용하고 싶습니다.

즉,

```text
설문
 ├─ 질문
 │   ├─ 선택지
 │   └─ 선택지
 │
 └─ 기사별 응답
```

구조를 유지하면서 관리자 화면에서 설문을 관리하고 싶습니다.

---

# 11. 삭제에 대한 요구사항

설문 삭제 시 해당 설문의

* 질문
* 선택지
* 기사별 설문 연결
* 응답

도 함께 삭제될 수 있다는 점을 고려해주세요.

현재 DB에는 `ON DELETE CASCADE`가 설정되어 있으므로
삭제 버튼을 누를 때 반드시 확인창을 표시하도록 하고 싶습니다.

예:

```text
정말 삭제하시겠습니까?

이 설문을 삭제하면

- 설문 문항
- 선택지
- 설문 대상자 연결
- 기존 응답

도 함께 삭제됩니다.

[취소] [삭제]
```

---

# 12. DB 구조 개선도 검토

현재 DB 구조를 무조건 그대로 사용할 필요는 없습니다.

실제 구현에 더 적합하다면 다음과 같은 개선도 제안해주세요.

예:

```text
survey_master

survey_id
survey_title
survey_subtitle
description
status
created_at
updated_at
```

디비 변경이 필요하다면 그 이유와 함께 DB 변경안을 제시해주세요.
단, 기존 시스템과의 호환성을 최대한 고려해주세요.

---

# 13. 중요한 구현 원칙

제가 원하는 것은 단순한 샘플 코드가 아닙니다.

현재 프로젝트에 실제로 넣을 수 있도록 다음 순서로 작업해주세요.

### 1단계

먼저 제가 제공한 현재 프로젝트 구조와 소스코드를 분석합니다.

### 2단계

현재 코드 구조를 최대한 유지하면서

* 어떤 파일을 새로 만들지
* 어떤 파일을 수정할지
* URL/라우팅 구조
* DB 변경사항
* HTML/Javascript 구조
* CRUD 처리 구조

를 설계합니다.

### 3단계

설계가 끝나면 실제 코드를 작성합니다.

### 4단계

기존 기능을 깨뜨리지 않도록 주의합니다.

특히 기존 기사(`drivers`) 데이터와 기존 설문 응답 데이터가
불필요하게 삭제되거나 변경되지 않도록 해야 합니다.

# 14. 최종적으로 원하는 관리자 메뉴

가능하면 다음과 같은 구조가 되었으면 합니다.

```text
설문 관리
│
├─ 설문 목록
│   ├─ 조회
│   ├─ 수정
│   └─ 삭제
│
├─ 새 설문 만들기
│   │
│   ├─ 기본정보
│   │   ├─ 제목
│   │   ├─ 부제목
│   │   ├─ 주요 안내사항
│   │   └─ 상태
│   │
│   ├─ 문항 관리
│   │   ├─ 질문 추가
│   │   ├─ 질문 수정
│   │   ├─ 질문 삭제
│   │   └─ 질문 순서 변경
│   │
│   ├─ 선택지 관리
│   │   ├─ 추가
│   │   ├─ 수정
│   │   ├─ 삭제
│   │   └─ 순서 변경
│   │
│   └─ 미리보기
│
└─ 응답 조회
```

# 15. 제가 원하는 답변 방식

먼저 코드를 무작정 작성하지 말고,

1. 현재 프로젝트 구조 분석
2. 현재 DB 구조 분석
3. 필요한 DB 변경사항
4. 화면 구성
5. URL/라우팅 설계
6. CRUD 처리 방식
7. 기존 코드와의 충돌 가능성
8. 구현 순서

를 먼저 설명해주세요.

그 다음 제가 확인하면 실제 코드 작성 단계로 넘어가고 싶습니다.

특히 기존 시스템을 최대한 유지하면서
점진적으로 추가할 수 있는 구조를 선호합니다.
