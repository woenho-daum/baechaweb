와이파이별 고정 아이피
------------------------
1단계: 저장된 와이파이 프로필 이름 정확히 확인하기
==============================
nmcli connection show
(출력 결과 중 NAME 항목에 나오는 이름(예: Company_WiFi, Home_WiFi)을 확인합니다.)

2단계: 회사 Wi-Fi 프로필에 고정 IP 설정하기
===============================
- 암호 없는 경우
nmcli dev wifi connect "회사_와이파이_이름"
nmcli connection modify "회사_와이파이_이름" ipv4.addresses 192.168.0.100/24 ipv4.gateway 192.168.0.1 ipv4.dns "8.8.8.8" ipv4.method manual
- 암호 있는 경우
nmcli dev wifi connect "회사_와이파이_이름" password "xxxx"
nmcli connection modify "회사_와이파이_이름" ipv4.addresses 192.168.0.100/24 ipv4.gateway 192.168.0.1 ipv4.dns "8.8.8.8,1.68.226.1" ipv4.method manual
192.168.0.100/24: 회사에서 사용할 라즈베리 파이의 고정 IP

192.168.0.1: 회사 공유기의 IP (게이트웨이)

3단계: 집 Wi-Fi 프로필에 고정 IP 설정하기
===============================
nmcli connection modify pwh ipv4.addresses 192.168.0.87/24 ipv4.gateway 192.168.0.1 ipv4.dns "8.8.8.8,1.1.1.1" ipv4.method manual
192.168.0.87/24: 집에서 사용할 라즈베리 파이의 고정 IP

4단계: 설정 적용 및 확인
=========================
nmcli connection up "현재_장소의_와이파이_이름"
ip a
wlan0 인터페이스에 각 프로필에서 지정한 고정 IP가 정상적으로 할당되었는지 확인하시면 됩니다. 
이렇게 설정해 두면 회사의 와이파이 범위 내에서는 회사 IP로, 집의 와이파이 범위 내에서는 집 IP로 자동 연결됩니다.

===========================
* * * * * 명령어
│ │ │ │ │
│ │ │ │ └───── 요일 (0 - 6, 일요일=0 또는 7)
│ │ │ └─────── 월 (1 - 12)
│ │ └───────── 일 (1 - 31)
│ └─────────── 시간 (0 - 23)
└───────────── 분 (0 - 59)
2. 특수문자 및 기호 사용법
    * (Asterisk): 모든 값(매 분, 매 시간 등)을 의미합니다.
    , (Comma): 특정 값들을 나열할 때 사용합니다. (예: 0, 30 은 0분과 30분)
    - (Hyphen): 범위 지정에 사용합니다. (예: 9-18 은 9시부터 18시까지)
    / (Slash): 주기(간격)를 설정할 때 사용합니다. (예: */10 은 10분마다)

3. 자주 사용하는 설정 예시
    매년/매월/매일 매시간 정각 (0 * * * *): 1시간마다 (매 정각) 실행
    매일 새벽 3시 30분 (30 3 * * *): 하루에 한 번 특정 시간에 실행
    매주 월요일 오전 9시 0분 (0 9 * * 1): 일주일에 한 번 실행
    매월 1일 자정 (0 0 1 * *): 한 달에 한 번 실행

4. duckdns 한시간마다 자동등록
{
    # */59 -> 59분마다 실행한다 (분의 최대값)
    #    0 -> 1시간마다 실행한다

    0 * * * * /opt/duckdns/duck.sh >> /var/log/duckdns/duck.log 2>&1
}

ssl 인증서 자동 갱신
------------------
Let's Encrypt 인증서는 유효기간이 90일이므로 정기적으로 갱신해 주어야 합니다. 
다행히 앞서 Certbot을 설치할 때 시스템에 자동 갱신 타이머(또는 cron 작업)가 함께 등록되었지만, 
인증서가 갱신된 이후에 Gunicorn이 새 인증서 파일을 읽을 수 있도록 웹서버를 재시작(Reload)해 주는 후처리 작업이 필요합니다.

1.dry-run으로 갱신 기능 점검하기:
Certbot 자동 갱신 테스트.터미널에 아래 명령어를 입력하여 갱신이 오류 없이 잘 작동하는지 시뮬레이션(테스트)해봅니다.
sudo certbot renew --dry-run
성공 여부 확인: The simulated renewal succeeded. 
메시지가 출력되면 자동 갱신 시스템이 정상 작동 상태임을 의미합니다.

2.post-hook 등록하기:
갱신 후 Gunicorn 자동 재시작 설정.
인증서가 성공적으로 갱신된 직후 Gunicorn(또는 systemd 서비스)을 재시작하도록 Certbot 설정에 후크(hook)를 추가하거나, 
systemd 디렉터리에 갱신 스크립트를 배치할 수 있습니다.
가장 간편한 방법은 renew 명령어 실행 시 --post-hook 옵션을 함께 사용하거나 
Certbot 설정 파일(.conf)에 리로드 명령을 지정하는 것입니다.
만약 systemd 서비스를 등록해 두셨다면, 
Certbot의 renewal 설정 파일(/etc/letsencrypt/renewal/baecha.duckdns.org.conf)을 열어 
renew_hook을 아래와 같이 추가할 수 있습니다:

sudo certbot renew --dry-run --renew-hook "echo 'Cert renewed, restart gunicorn manually or script here'"

오랜만에 서버를 켰을 때 수동 갱신 방법
--------------------------
서버를 오랜만에 켜신 후 터미널에 아래 명령어를 입력하여 현재 인증서 상태를 확인하고 갱신을 진행하시면 됩니다.
sudo certbot renew

인증서 유효기간 지나면
=================
sudo pkill gunicorn
sudo certbot renew --force-renewal

Fail2ban 설치
======================
1.패키지 설치 및 실행하기:
라즈베리 파이 터미널에 아래 명령어를 입력하여 Fail2ban을 설치합니다.
sudo apt install fail2ban -y

2.403 에러 패턴 지정하기:
커스텀 필터(Filter) 생성.
Flask의 Gunicorn 접근 로그에서 403 응답을 발생시키는 악성 스캔 봇의 IP를 잡아내기 위한 필터를 만듭니다.
sudo nano /etc/fail2ban/filter.d/flask-scanner.conf
파일 안에 아래 내용을 입력하고 저장합니다 (Ctrl + O, Enter, Ctrl + X)
[Definition]
failregex = ^<HOST> - - \[.*\] "(GET|POST|HEAD).* (403|404) .*$
ignoreregex =

3.차단 규칙 및 연동 설정하기:
제일(Jail) 설정 추가.
Fail2ban이 어떤 로그를 보고 어떤 방화벽(UFW)을 통해 차단할지 설정합니다.
sudo nano /etc/fail2ban/jail.local

파일에 아래 설정을 추가합니다 (기존 내용이 있다면 하단에 붙여넣습니다).
[flask-scanner]
enabled = true
port = http,https
logpath = /home/pi/baechaweb/Survey/gunicorn-access.log
filter = flask-scanner
maxretry = 3
bantime = 86400
findtime = 600
banaction = ufw


설정 의미: 60초(findtime) 동안 비정상 경로 접근으로 3번 이상(maxretry) 403/404 에러를 유발하면, 
UFW 방화벽을 통해 해당 IP를 24시간(bantime = 86400) 동안 차단합니다.

4.설정 적용하기:
Fail2ban 재시작.
작성한 설정을 반영하기 위해 Fail2ban 서비스를 재시작합니다.
sudo systemctl restart fail2ban
성공 여부 확인: 
sudo fail2ban-client status flask-scanner 
명령어를 입력했을 때 감시가 정상적으로 시작되었는지(Status) 확인합니다.
